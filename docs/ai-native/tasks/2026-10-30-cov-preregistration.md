## Question
Does extending the expert's training support to x ∈ [0.34, 0.38) explain the boundary grasp failure (too‑deep grasp → box seated against the palm → 3–5 cm placement offset) of the frozen C0/S1 policies, and does it change the C0/S1 trade‑off?
## Design (as frozen)
- **Data.** Original 60 demos (x 0.38–0.45, y 0.07–0.13, yaw ±0.20, V1 split 54/6). **EXT** = original + 30 new expert demos, x ~ U[0.34, 0.38), same y/yaw ranges (`data/collect_demos_region.py`, base seed 40, same expert/cameras/light jitter 0.15). **VOL** (volume control) = original + 30 new demos from the ORIGINAL region (base seed 41): more data, no new coverage. New val demos: 3 of 30 (default_rng(0)); original episodes keep their V1 split.
- **Branches / seeds.** ext_c0, ext_s1 (paired seeds), vol_c0, vol_s1; new independent seeds 3 (and 4 for EXT as registered, see deviation D1). Training identical to E0: 5400 steps, batch 16, lr 1e‑4, 1 loader worker, 3 torch threads, train‑only statistics, S1 floors 0.02 rad / 0.002 m, C0 no floor.
- **Evaluation per checkpoint.** (i) the frozen x‑sweep (`outputs/xsweep/xsweep_config.json`, sha256 `6c59292d…596c`, 15 x × 4 blocks = 60 poses); (ii) shortcut sensitivity on NOM seed 21 ids 0–19 (unperturbed, `right_mean`, `right_jitter_small`; SI = perturbed/unperturbed successes); (iii) open‑loop MAE on the 6 original validation episodes; (iv) latency from the evaluation logs; replay (`eval/xsweep_replay.py`) for grasp offset a_close, slip, palm/finger contact, final placement error.
- **Hypotheses (rules frozen).** C1 boundary success: for both arms EXT success over x ∈ [0.34, 0.37] ≥ same‑arm baseline mean + 20 pp and ≥ 75 %, each EXT seed ≥ baseline + 10 pp. C2 volume control: VOL ≤ baseline + 10 pp at x ≤ 0.37 (else volume confound). C3 grasp position: |a_close − expert| ≤ 1.0 cm at x ∈ [0.34, 0.37] and improved ≥ 1.5 cm vs baseline. C4 trade‑off: S1 − C0 at x ≤ 0.37 ≥ −10 pp (paired by EXT seed). C5 no in‑support regression (≥ baseline − 10 pp, x 0.38–0.45). C6 shortcut retained (S1 SI ≥ 0.90 on both modes; C0 SI ≤ 0.25). C7 effect is local (|EXT − baseline| ≤ 15 pp at x ≥ 0.46). C8 latency within ±25 %. Overall: COVERAGE EXPLAINS if C1 ∧ C2 ∧ C3; PARTIAL if C1 holds but C2 or C3 fails; NOT EXPLAINED if C1 fails. All else exploratory.
- **Uncertainty.** Across training seeds: per‑seed values and sign consistency (baseline n = 3; EXT/VOL now n = 1 per arm, see D1); across pose blocks: block‑resampling bootstrap and per‑block tables. EXT/VOL vs baseline are comparisons between independent training seeds (unpaired). Known confounds: fixed 5400 steps ⇒ fewer steps per demo with 90 demos; seed‑0 baselines used 4 threads, all new runs 3.

## Protocol deviations (recorded before any EXT/VOL result was seen)
- **D1 (compute, user decision 2026‑10‑30).** First‑200‑step speed of the first run was 1.03 s/step (E0 runs: 0.74–0.79; this VM ≈ 25 % slower than the E0 VM, also visible in the x‑sweep at 18 s/episode vs 15). Projection for the six registered runs: ≈ 13.9 h **remaining** wall‑clock (≈ 94 min training + ≈ 40 min evaluation per run), ≈ 17 h in total including data work — above the registered 14 h stop rule. Decision (option 2): **EXT seed 4 for both arms is not run**; EXT seed 3 and VOL seed 3 run for both arms (4 runs, ≈ 8.9 h remaining, ≈ 12.5 h total incl. data work, inside the 14 h rule). The two skipped runs are marked by `SKIPPED` marker files (`outputs/checkpoints/cov_ext_*_seed4.done`, `outputs/cov/eval/ext_*_seed4.done`), no training/evaluation took place. The frozen config is unchanged.
- **D1 consequences (pre‑declared).** Every EXT and VOL branch has one training seed. C1's "each EXT seed" clause reduces to the single seed; C4's pairing by EXT seed reduces to one pair (no interval, descriptive); C6 and C3 are evaluated on one seed per arm; C2 (coverage vs volume) is **exploratory**; hypotheses that need seed‑to‑seed spread cannot be called confirmed. The report will not claim completion of the full C1–C8 set and will label every verdict "single‑seed".
- **D2 (gating).** After the two EXT checkpoints are evaluated their training health, grasp offsets, success by x and failure modes are inspected; VOL runs proceed only if no serious problem is found (the queue starts VOL training right after the second EXT evaluation, inspection happens while it runs; a serious problem would stop the queue).
