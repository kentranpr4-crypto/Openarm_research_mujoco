## 1. Gate v3 — changes since the last draft (all prospective; draft config sha256 `87984e128d1e085bf09fab263dfc95c4893b33ca905e4337ff9cbaa8a1cd6604`, not a frozen path)
Tests: `eval/test_wm4_gates.py` **85/85 PASS** (geometry 12, aggregation 4, G3 32, G7 35, config 2 — see `outputs/gates_v3/unit_tests.json`).
- **G3 rare-label operating point, threshold-selection rule.** τ = (1 − 0.04) quantile of the model's scores on the NEGATIVE at-risk windows of a **calibration split (validation)**; evaluation labels are never used to choose τ; τ is then fixed; the evaluation sets report TPR(τ) and FPR(τ); gate: TPR ≥ 0.70 **and** FPR ≤ 0.05. Calibrating at 4 % leaves margin below the 5 % limit (proposal). Calibration needs ≥ 500 negative windows, otherwise NOT_EVALUABLE; without a calibration split the rare-label operating point is NOT_EVALUABLE (never PASS). Tests: τ is bit-identical when the evaluation labels are permuted; too few calibration negatives ⇒ NOT_EVALUABLE; an evaluation FPR above 0.05 FAILS even with perfect recall; oracle PASS (TPR ≥ 0.70, FPR ≤ 0.05), reference-as-model FAIL, label-shuffle FAIL, low-recall model FAIL. Hard-subset rule (prevalence ≥ 5 %, support) and aggregation (FAIL outranks NOT_EVALUABLE; NOT_APPLICABLE is excluded and never a pass) unchanged and tested.
- **G7**: yaw baseline-relative ratio ≤ 1.10 / upper CI ≤ 1.25, static ≤ 0.01 rad, relative ≤ 3.0 with floor 0.003, hnorm 0.20, rotating 0.02, tumbling 0.30 — kept as you specified. **Both** geodesic distances are reported: the box-symmetric one (gating) and the full quaternion geodesic (reported separately, not gating).
- **D2 symmetry validity for the blue box (checked):** geometry — one collision cuboid (half-extents 0.025 × 0.020 × 0.020 m) centred on the body, uniform mass 0.05 kg and friction (`sim/lab_scene.py`); the 8 vertices map onto themselves under the three 180° body rotations (tested). Appearance — one uniform-colour material (rgba 0.12/0.33/0.95), no texture, visual twin of identical size ⇒ no marking that distinguishes the two ends/faces. Task semantics — `eval/metrics.py::task_labels` uses box position, z and speed only (no orientation); grasp success depends on the contact geometry, which a 180° rotation about a body axis leaves unchanged. A 90° yaw is **not** a symmetry (extents differ in x and y; tested), so D2 never forgives it. Because the y and z extents are equal, the true symmetry group is larger (90° rotations about the body x axis also preserve the box; tested) — D2 is a conservative subgroup. In the development windows D2 matters little: full-minus-symmetric geodesic > 0.1 rad in 0.02–0.5 % of windows.

## 3. E1-lite (exploratory diagnostic; not model selection; I-1 not used)
Setup as pre-registered in `eval/e1_lite.py`: frozen original WM3-B trunk, v1 120-D input contract and original normaliser; a new per-step head Linear(256→1) (× 0.0166) on cached trunk features; arms H_old (MSE of normalised yaw delta over all steps, std 0.0529) and H_mask (masked Huber, δ 0.05 rad, robust scale 0.01545, v2 geometric mask aligned by episode/t) share trunk, initialisation, seed 0, batches, AdamW 2e-3, 10 epochs. Sanity: the existing yaw head is reproduced **exactly** from the cached features (max |Δ| = 0.0 in all splits); v1 and v2 yaw targets agree to 4.8e-7 rad at valid steps. Compute: **436 CPU-s = 0.121 CPU-h** (cap 0.3), 181 s wall; no trunk training, no architecture change, no tuning after the run.

Pre-registered decision: rotating improvement requires E_mask / min(E_P0, E_ridge) ≤ 0.90 with upper bound < 1.0. Observed (development, K = 20, rotating): best reference = ridge; **ratio 1.036 [0.995, 1.086]** (H_old: 2.48 [2.16, 2.86]; existing head: 2.50 [2.17, 2.88]). ⇒ **rotating improvement NOT demonstrated**. H_mask ≤ H_old: yes (2.4× lower). Gate v3 G7 on the development splits (legacy yaw outputs; orientation components NOT_EVALUABLE for all): existing head FAIL (yaw ratio 2.67, static 0.043); H_old FAIL (2.63, 0.044); **H_mask yaw ratio 1.017 PASS (upper 1.069 PASS), static abs 0.0093 PASS, diff vs persistence upper 0.0072 PASS, static relative 3.095 FAIL (> 3.0)** ⇒ gate FAIL on one marginal component; on validation H_mask passes all evaluable components (relative 2.28; verdict NOT_EVALUABLE only because orientation is not evaluable). Box/contact/joint/event outputs are bit-identical by construction (only Y_b[:,:,3] is replaced).
Reading (exploratory): (i) the same linear head on the same frozen features with the old objective **reproduces the hallucination** (H_old ≈ existing head) — so the failure is not an optimisation accident of the original head; (ii) changing only the loss (mask + Huber + robust scale, bundled — the three are not separated here) removes ~85 % of the static error and brings yaw to the level of ridge/persistence, but **not below ridge on rotating windows**, i.e. there is no evidence of yaw skill in these features beyond a linear baseline; (iii) persistence remains the best static predictor (0.0041 vs 0.0140), so "no rotation unless interacting" remains hard to beat on stable windows. Limits: head-only (cannot show what the trunk could learn under a different loss), one seed, development splits, loss factors bundled.
Per your rule, **E1 full is not triggered.**

## 5. Recommendation — next experiment with the highest information gain
1. **Do not run E1 full now**: E1-lite already shows the loss is sufficient to remove the hallucination at head level, and that the features carry no yaw signal beyond ridge; the remaining E1 arms (≤ 7.2 CPU-h) would mostly test trunk-level and representation effects with a low prior of beating ridge on yaw.
2. **E1-lite-B (≈ 0.15 CPU-h, needs approval): frozen-trunk rotation-vector head** (+ ridge rotation-vector baseline, persistence) on the v2 targets. It would make the G7 orientation component evaluable for the first time (1 153 development windows / 78 groups of singular + tumbling), measure whether the trunk features carry any orientation information on tumbling, and directly test the "masking hides tumbling" risk.
3. **E1-lite-C (≈ 0.2 CPU-h): loss-factor ablation on the same frozen trunk** — mask-only, Huber-only, robust-scale-only, full — to attribute the effect that is bundled in H_mask.
4. Then decide between the paired multi-seed (13.5 CPU-h; needs budget confirmation) and the I-2 protocol (freeze first).
