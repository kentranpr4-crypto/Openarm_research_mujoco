## A. Definitions
t_close = first control step whose executed left-gripper target < 0.040 m (row t = observation before action t; ACT closes at step 40–47, expert 42–49). Box frame: origin box centre at t_close, x_f = [cos ψ_box, sin ψ_box, 0] (the expert's finger direction), n = [−sin, cos, 0], z up. df/dn/dz = TCP − box centre [cm]. ACT−expert errors compare the same pose, each at its own t_close. a_close = box centre − TCP along the TCP z-axis [cm] (xsweep definition). yaw error = hand yaw − box yaw [rad]. Servo lag = action[t−1] − state[t].

- Integrator implicitfast, timestep 0.001 s, 50 substeps per 20 Hz control step; solver settings otherwise MuJoCo defaults (Newton, pyramidal cone, condim 3, solimp default) — not overridden in the XML. Collision class: friction 1/0.01/0.01, solref 0.005; box geom friction 0.8 (MuJoCo takes the max → effective 1.0), mass 0.05 kg, size 0.05×0.04×0.04 m. Finger and hand collision geoms are STL meshes (`finger_collision`, `hand_collision`). Friction/mass are **placeholders** per `lab_scene.py`.
- Gripper actuator (v1): position servo kp 5664 N/m, kv 113.3, force limit ±150.8 N, slide joint 0–0.044 m, ctrlrange −0.005…0.044 m; `finger_joint2` tied to `finger_joint1` by an equality constraint (one DOF).
- **Expected grip force:** F ≈ kp·(q_contact − cmd). From G1 (cmd 0.016 → 25.7 N, 0.008 → 70.7 N) q_contact ≈ 0.0205 m for both; for cmd 0.012 → 48 N (observed median 47.9 N), ACT cmd 0.0114 → 51 N; far below the 150.8 N limit. I: the 26–71 N values are set by the servo law and the commanded interpenetration, **not an independent measure of grasp quality**, and real-hardware force limits/driver behaviour are unverified (audit doc: kp/kv vs real driver NOT_CHECKED).
- **7–8 contacts per grasp:** `finger_contacts` counts MuJoCo contact points; box–mesh pairs generate several points per finger. I: 7–8 ≈ 2 fingers × ~4 points of one grasp, not 7–8 independent grasps (per-geom counts were not stored → inference).
- Sim-to-real limits: placeholder friction/mass; stiff contact (solref 0.005) with 1 ms step; mesh-manifold contacts; gripper unit/force law unverified; privileged state; expert gravity-compensation offsets in the commands; box centre pose exact.

## D. Prospective ACT-anchored candidate generator — DESIGN ONLY
Three families, kept distinct:
1. **Perturbations around the expert grasp (oracle-pose, G1-style).** Used only as a causal bracket: expert grasp + offsets drawn from the *measured ACT−expert error distribution*. Question: does an expert grasp with ACT-like depth error (+2…+4 cm) reproduce palm contact and loss of grasp? (If not, the association in B is not about geometry.)
2. **Corrections around the ACT-predicted grasp (primary).** Nominal = the ACT's own chunk (control; correction 0 reproduces ACT bit-exactly). Candidates modify the ACT's own commanded targets in the chunk containing the close command: forward kinematics of the commanded joint targets → TCP target → shift in the box frame by (Δf, Δn, Δψ) → IK → absolute joint targets (same actuator mapping, then the same clip→slew chain), blended over a fixed number of steps from the last executed target; optional gripper-channel delay k steps to let the arm settle. ACT is then re-queried normally at the next chunk boundaries. The correction magnitude comes from the geometry error to the oracle reference (**oracle correction = upper bound**; deployable only with a perception estimate).
3. **Pure oracle-pose geometry** (G1): not repeated.
Parameters varied (family 2): Δf (depth), Δn (lateral), Δψ (yaw), k (closing delay). Not varied: aperture (ACT already inside G1 range), closing speed, height (error ≤0.6 cm).
Range selection (outcome-agnostic): levels = pooled ACT−expert error quantiles p10/p90 from this audit — depth −2.2/+3.1 cm, lateral −1.3/+1.0 cm, yaw −0.16/+0.16 rad — applied as *corrections of the opposite sign* (i.e. levels ±; sign convention fixed in the freeze), delay k ∈ {0, 8} steps (8 = 4 × the 2-step servo time constant measured in B8; physical settle time, not outcome-derived). Design: 2^(4−1) fractional factorial (8 runs, D = ABC) + the ACT nominal = 9 candidates. Additionally an “oracle-cancel” candidate (Δ = −(ACT−expert error)) is reported as a separate bound, not counted in the 9.
Feasibility: FK/IK with the expert's `ArmIK`; reject if IK residual >2 mm / 0.03 rad, ctrlrange or slew violation, robot–obstacle contact; validity fraction must be ≥80 %. Distinctness after clip/slew measured as in G1.
Expected sensitivity (from B, not from G1 outcomes): outcome variance should appear when the ACT depth error exceeds ≈ +1.5 cm (failure 23 % → 74–87 %, palm 2 % → 26–100 %); no sensitivity expected where the ACT error is already within ±1 cm.
Split and leakage prevention: ranges derived from the 60 xsweep poses; the experiment uses **new** poses (new RNG namespace, min-distance rejection against xsweep/Stage-1/branching/G1/indep poses, x ∈ 0.34–0.38 over-sampled where errors are large), 48 poses, 1 ACT checkpoint (c0_seed0) as the policy; poses development-only afterwards. The oracle reference pose enters only the correction magnitude of the oracle-cancel bound; plans/labels never feed back into the ACT input.
Procedure: replay ACT to the chunk boundary before the close command (t = 40), snapshot (the validated `mj_copyData` machinery), apply each candidate to the chunk, continue with ACT re-queries to the end of a pre-registered hold window (≈t 90), label with the frozen lift-and-hold definition of G1 (+palm, slip, drop; NOT_EVALUABLE otherwise).
Primary metrics: GRASP_SUCCESS rate by candidate and oracle best-of-9 headroom vs the ACT nominal (state-level binary gap), pose-cluster bootstrap; palm-free success; main effects of Δf/Δn/Δψ/k; oracle-cancel success; validity/distinctness. Stop rules: validity <80 %; >80 % of states without headroom; snapshot/semantics failure; CPU cap.
Compute: ≈0.7 s/branch (3 ACT queries + 50 steps) × 432 branches ≈ 300 s + prefix/setup/tests ≈ 0.12–0.15 CPU-h; proposed cap **0.25 CPU-h** for everything.

## E. Is a new experiment scientifically justified?
Yes, narrowly: the audit shows a strong dose–response (|depth| AUROC 0.89; ≥+3 cm → 100 % palm contact and 87 % failure) that G1 could not test because its ±1 cm range covers only 11 % of failing ACT grasps. The G1 stop rule stands for the oracle-pose family; a corrections-around-ACT experiment answers a different, still open question: whether *correcting the ACT’s grasp geometry* removes the palm/loss failures (oracle headroom for any WM ranking). It does not justify GF-WM training; only a positive headroom result with an oracle correction would, and then only with a perception-based estimate in place of the oracle. Needs separate approval; none of this was run.
