## 1. X4 revised text (E3 PLACEMENT_SUCCESS)
E3 is TRUE iff all hold, in this order: (1) `target_arrival`; (2) `release_command` (intended: inside R_REL, <= Z_REL above rest); (3) `release_confirmed` (verified); (4) `placement_settled` whose 10-row window STARTS at/after the verification row. Three timestamp kinds are kept apart: ONSET (release_command, release_physical_onset, release_confirmed_onset), VERIFICATION (release_confirmed) and DECISION (e3_decision_row). Events (row indices; row i = observation before action i; a command issued at row i first shows in row i+1):
| Event | Definition | Type |
|---|---|---|
| target_arrival | first start s in [t_lc, t_release_command] with box d_xy < R_REL (0.05 m) and z - z_rest <= Z_REL (0.05 m) on K_ARR = 3 rows (run may extend past the command row) | observation |
| release_command | unchanged (running-minimum rise of the commanded gripper target >= 4 mm for 2 command rows; issue row) | command |
| release_physical_onset | measured finger position `g_meas` >= 4 mm above its running minimum since t_ga for 2 rows (timeline only) | observation |
| release_confirmed_onset (rc) | first start s in [t_cmd+1, t_cmd+CONFIRM_BUDGET = +40] with NOT clamped AND opened on K_REL = 3 consecutive rows, where clamped = held (n_L, n_R >= 1 and F_L, F_R >= F_HELD = 2.5 N) and opened = `g_meas` - running minimum of `g_meas` since t_ga >= OPEN_CONFIRM = 8 mm (t_cmd = release_command row). Stamped at the FIRST row of the confirmed state; only recorded once all K_REL rows exist | onset (observation) |
| release_confirmed (rv) | `rv = rc + K_REL - 1`: the first row at which all K_REL required observations exist; the release is never verified earlier | verification |
| placement_settled | first start s >= rv (start <= rv+31) with box d_xy < 3 cm, abs(z - z_rest) < 6 mm, speed < 0.02 m/s AND not clamped, on K_SETTLE = 10 rows; the 10-row window therefore cannot start before the verified release | observation |
| e3_decision_row | first observed row from which E3 is fixed: SUCCESS `ts+K_SETTLE-1`; NOT_SETTLED `rv+SETTLE_BUDGET`; RELEASE_NOT_CONFIRMED `t_cmd+CONFIRM_BUDGET+K_REL-1 (= t_cmd+42)`; NO_TARGET_ARRIVAL `t_cmd+K_ARR-1`; none while undecided | label decision |
Tray-supported vs gripper-held: an object counts as mechanically held while clamped (both fingers loaded); it counts as tray-supported only when it rests at tray height (|z - z_rest| < 6 mm) AND is not clamped AND the fingers have opened by >= 8 mm. Command-only opening (jam) never confirms a release.
Policy (prespecified): confirmation not found and rows through `t_cmd + 40 + 3 - 1` observed -> PLACEMENT_FAILURE/RELEASE_NOT_CONFIRMED, E3 FALSE; observation (trace or horizon) ends earlier -> TIMEOUT, E3 CENSORED; confirmed but window incomplete at the end -> TIMEOUT / CENSORED; no arrival evidence -> PLACEMENT_FAILURE/NO_TARGET_ARRIVAL; settle fails after the budget (`rv + 40`) -> PLACEMENT_FAILURE/NOT_SETTLED. `g_meas` is required: missing or non-finite -> INVALID.
Ambiguity bands added (fixed): OPEN_CONFIRM +-2 mm; K_REL, K_ARR +-1 (plus the existing F_HELD +-0.5 N).
Rationale of values: 8 mm = twice the 4 mm onset threshold, an unmistakable opening (> contact tolerance) per finger; K_REL = K_LOSS = 3 and K_ARR = 3 follow the existing debounce convention; budget 40 = LIFT_BUDGET.

## 2. Effect by logical definition
- **E1** unchanged (depends on t_ga only). **E2** unchanged (window and loss rules use the release COMMAND and are not touched). **E2 TRUE with E3 FALSE** is consistent, not a contradiction: E2 asks whether the grasp was retained until the intended end of the carry (the release command); if the opening then fails physically (jam), the carry was retained (E2 TRUE) but the placement did not happen (E3 FALSE, RELEASE_NOT_CONFIRMED). Tested.
- **E3 is NOT monotone** relative to pre-X4 (correction of an earlier claim that it could only become stricter). It is stricter in the sense that TRUE now needs a verified release (jammed gripper: SUCCESS -> FAILURE; incomplete observations: SUCCESS -> TIMEOUT/CENSORED) and `placement_settled` is stamped later (the window starts at the verification row). But the settle budget now runs from the verification row instead of the command row, so a box that rests late can be PLACEMENT_FAILURE pre-X4 and PLACEMENT_SUCCESS post-X4 (synthetic example, tested: physical release 24 rows after the command, box resting from t_cmd+37). Any comparison with pre-X4 labels must therefore be case-by-case, not directional.
- Terminal labels: PLACEMENT_SUCCESS can become PLACEMENT_FAILURE or TIMEOUT and PLACEMENT_FAILURE can become PLACEMENT_SUCCESS; CARRY_DROP, RELEASE_OUTSIDE_TARGET and ACQUISITION_FAILURE rules are unchanged.

## 3. Synthetic before/after and test history (pre-X4 labeller read from git `b838870`)
E1 and E2 are identical on every synthetic case (104 family cases + 5 hand-built). Differences: jammed gripper SUCCESS/TRUE -> FAILURE/RELEASE_NOT_CONFIRMED/FALSE; every other successful case keeps SUCCESS with `placement_settled` 2 or more rows later (the window now starts at the verification row); one constructed late-settling case is FAILURE pre-X4 and SUCCESS post-X4. Historical frozen G2a/G1/Stage-1 results: no non-G2b module imports the labeller; nothing re-labelled.
Boundary tests (confirmed-state onset at t_cmd + 39 / 40 / 41 / 42): 39 and 40 verified (SUCCESS), 41 and 42 RELEASE_NOT_CONFIRMED with decision row t_cmd+42; with only K_REL-1 rows of the confirmed state there is no release_confirmed event and the label is TIMEOUT / CENSORED.
Test history (kept for transparency): run 1 of the X4 suite: 76 failures, all from the synthetic generator (it did not make the fingers leave the box on release) - generator fixed, labeller unchanged; run 2: 1 failure, an off-by-one in a test's cut length for the decision row - test corrected to the contract (`N-1 >= t_cmd+40+3-1`), no assertion removed or relaxed; review-round run 3: 1 failure of a newly added non-monotonic example whose construction shifted the acquisition as well (report kept as `outputs/g2b_impl/labeller_x4_report_run3_FAIL_nonmonotone_example.json`) - example rebuilt; run 4: PASS, 48 boundary tests, 0 failures, 312 + 312 traces. The settle window start moved from the run start `rc` to the verification row `rv` in the review round (item 4 of the review); this is inside the approved X4 scope.
Threshold provenance: OPEN_CONFIRM, K_REL, K_ARR and CONFIRM_BUDGET were fixed before any X4 test from geometry and the existing K/budget conventions; no historical outcome was used to tune them and none was changed after the tests.

## 4. Prepared (NOT executed) minimal intervention benchmark
Purpose: measure the real cost of branches whose execution path differs from nominal. Scope: ONE known development pose (G2a idx 3000), snapshot at t = 40, horizon 160, branches: c0 (reference), **IK-heavy** O3 (depth+lateral+yaw) and D1 (2 cm shallower), **non-IK** D2 (close delayed 8) and S0 (hold 8); trace recorder on. Report CPU per branch split into correction/IK, ACT, `mj_step`, recorder; startup once. Expected: setup 17 s + Kin init + 5 x 2.8 s + IK (G2a measured about 0.09 s per branch; O3 with 20 IK solves per chunk is the unknown) ~ 40 s; proposed hard cap 0.03 CPU-h = 108 s aggregate (separate from the 0.30 G2b cap, NOT AUTHORIZED); optional second pose only if the first stays under 60 s. Stop on first failure or on the guard; no retries; no treatment-effect statistics; no labels used for any decision. Permissions needed: simulator + ACT rollouts, read-only import of the frozen G2a correction code (`eval/g2a_act_corrections.py`: Kin, correct_chunk), 1 known pose, a ledger file.
